# 项目背景（PROJECT CONTEXT）

## 概述

这是一个长期运营的 AI SaaS 平台，构建于 Cloudflare 生态之上。平台通过统一的基础架构为多个 AI 应用提供服务，主要面向中国大陆用户。

---

## 技术栈

### 前端
- **框架**：React + TypeScript
- **构建工具**：Vite
- **样式**：CSS-in-JS 或组件库（待定）
- **状态管理**：Context API 或 Zustand（待定）

### 后端 / Serverless
- **运行环境**：Cloudflare Pages Functions
- **托管平台**：Cloudflare Pages
- **边缘计算**：Cloudflare Workers（仅在 Pages Functions 无法满足时使用）

### 数据存储
- **关系数据库**：Cloudflare D1（SQLite 驱动）
- **键值存储**：Cloudflare KV
- **对象存储**：Cloudflare R2
- **缓存**：Cloudflare CDN 缓存层

### AI 基础设施
- **AI 提供商抽象层**：支持多提供商（OpenAI、Anthropic、Google、Ollama 本地模型）
- **Prompt 引擎**：集中式 Prompt 管理系统
- **知识库引擎**：RAG（检索增强生成）管道
- **AI Queue**：异步任务处理系统
- **报告引擎**：报告生成与分发系统

### 部署
- **CI/CD**：Cloudflare Pages 自动从 Git 部署
- **环境**：开发、预发、生产
- **域名**：单一自定义域名（确保国内可访问）

## 关键约束条件

### 一、中国大陆网络兼容性（最高优先级）

每次架构决策都必须优先考虑国内可访问性：

- 尽量使用同域 API
- 优先使用 Pages Functions 部署
- 通过一个自定义域名服务所有请求
- **绝对不允许向用户暴露 workers.dev 域名**
- 尽量减少跨域请求
- 尽量减少 DNS 查询
- 尽量减少 TLS 握手次数
- 实现异常自动重试策略
- 实现合理的超时处理
- 实现优雅降级机制

### 二、Cloudflare 平台限制

所有代码必须符合 Cloudflare 运行环境约束：

- 不能使用 Node.js 内置模块
- 每个请求 CPU 时间有限
- 请求大小有限制
- 文件系统访问受限
- 流式传输支持但有局限
- 需要状态管理时使用 Durable Objects

### 三、生产级质量标准

这是生产平台，不是原型。所有代码必须满足：

- 生产级别错误处理
- 结构化日志记录
- 性能监控就绪
- 安全最佳实践
- 文档完整
- 向后兼容保证

## 架构理念

- **一个平台，多个应用**：一套共享基础设施，多个前端应用
- **共享服务**：认证、计费、AI 处理、存储、日志全部共享
- **API 优先设计**：所有功能通过定义良好的 API 暴露
- **渐进增强**：核心功能全平台可用；高级功能在支持的环境下增强体验
- **优雅降级**：上游依赖不可用时进入降级模式
- **水平扩展**：面向 Cloudflare 全球边缘网络设计
- **国内优先**：每个设计决策首先考虑中国大陆用户的体验
