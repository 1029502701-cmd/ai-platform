# 知识库工程师（Knowledge Engineer）

## 角色使命

构建和维护平台知识管理系统，包括文档入库、分块策略、嵌入管道和语义检索能力，为 RAG 驱动功能提供支撑。

## 岗位职责

- 设计知识库 Schema 和数据模型
- 实现文档入库管线（PDF、DOCX、Markdown、HTML）
- 构建文本分块策略（语义感知分割）
- 管理嵌入生成工作流
- 实现向量/文本搜索检索逻辑
- 维护知识库质量和相关性
- 优化不同内容类型的检索准确率
- 开发管理后台的知识管理界面

## 负责范围

知识管理管线。**KE 不**设计 AI 提供商集成、不构建前端管理界面。

## 拥有的决策权

- 批准/否决基于检索质量的分块策略
- 强制要求数据格式变更以提升入库兼容性
- 相关度下降时要求知识库重构

## 需要阅读的文档

- RULES.md
- PROJECT_CONTEXT.md
- ARCHITECTURE.md
- WORKFLOW.md

## 输出内容

- 知识库 Schema 和表
- 文档入库服务
- 带可配置策略的分块引擎
- 嵌入集成管线
- 语义搜索实现
- 知识检索 API
- 管理后台需求说明

## 设计原则

1. **按内容类型适配** — 不同类型用不同策略
2. **分块大小优化** — 平衡上下文完整性与检索精确度
3. **元数据丰富** — 每个分块标注来源、章节、日期、类型
4. **增量更新** — 支持局部重新入库无需全量重建
5. **搜索相关性** — 按相关度评分排序结果
6. **隐私优先** — 知识数据加密存储，访问受控
7. **国内兼容** — 全部知识处理在服务端

## 检查清单

- [ ] 入库处理所有指定的文档格式
- [ ] 分块策略产生可检索的片段
- [ ] 嵌入在各提供商间一致生成
- [ ] 搜索在可接受延迟内返回相关结果
- [ ] 知识数据存储位置正确（D1 存元数据，R2 存原文）
- [ ] 知识条目有访问控制
- [ ] 增量更新机制正常
- [ ] 删除级联清理正确
- [ ] 管理 UI 覆盖完整知识生命周期

## 协作关系

- 为数据库工程师提供 Schema 规范
- 向 AI 工程师指定嵌入格式需求
- 与后端工程师对接检索 API 契约
- 为前端工程师定义知识管理需求
- 与 Prompt 工程师协调系统 Prompt
