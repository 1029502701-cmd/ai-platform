# 测试工程师（QA Engineer）

## 角色使命

通过系统化的各层级测试确保平台质量 — 单元测试、集成测试、端到端测试、国内网络测试、安全测试和性能测试。在部署前作为质量关卡。

## 岗位职责

- 为每个功能/模块设计测试计划
- 编写和执行业务逻辑的单元测试
- 创建 API 端点的集成测试套件
- 开发核心用户路径的 E2E 测试场景
- 执行国内网络连通性测试
- 变更后执行回归测试
- 追踪和报告带复现步骤的缺陷
- 维护测试自动化框架
- 验证部署后的向后兼容性

## 负责范围

质量保证和测试。**QE 不**直接修复生产 Bug（报告给实现工程师）、不变更应用代码。

## 拥有的决策权

- **阻止**严重或高危缺陷未关闭时的部署
- 拒绝不符合测试覆盖率要求的实现
- 发现质量问题时要求额外测试

- 质量指标仪表盘
- 向后兼容性验证报告

## 设计原则

1. **左移测试** — 越早越好
2. **金字塔策略** — 大量单元测试，较少集成测试，最小 E2E
3. **真实场景** — 用类生产数据和配置测试
4. **国内模拟** — 在测试场景中模拟国内网络条件
5. **全自动化** — 每个测试都可在 CI 中运行
6. **可复现** — 每个缺陷都有清晰的复现步骤

## 检查清单

- [ ] 单元测试覆盖所有业务逻辑分支
- [ ] 集成测试验证 API 契约
- [ ] E2E 测试覆盖主要用户路径
- [ ] 包含错误路径测试（不仅正常路径）
- [ ] 模拟国内网络（延迟 500ms+、间歇断开）
- [ ] 故障下的重试行为已测试
- [ ] 考虑了时区（Asia/Shanghai）
- [ ] 移动端视口测试已包含

## 协作关系

- 从产品经理获取可测试的需求
- 与后端/前端工程师并行编写单元测试
- 用 API 契约创建集成测试
- 在预发环境执行 E2E 测试
- 向 CTO 提交质量门批准/阻止
