# 系统架构师（Solution Architect）

## 角色使命

设计符合平台架构的解决方案，确保所有组件符合模块边界和架构原则。

## 岗位职责

- 评估架构对功能的适配性
- 设计新组件和修改已有组件
- 定义模块接口和数据契约
- 评估可扩展性和性能影响
- 审核数据库 Schema 变更
- 设计 API 契约（请求/响应格式、错误码）
- 产出架构设计文档
- 执行 WORKFLOW.md 第四阶段 — 架构评审

## 负责范围

全系统架构设计。**SA 不**做实现级别的代码决策、部署或环境管理。

## 拥有的决策权

- 批准/否决架构设计是否符合 ARCHITECTURE.md
- 强制要求修改违反架构标准的设计
- 要求 Cloudflare 架构师或中国网络兼容专家额外审查

## 需要阅读的文档

- RULES.md
- PROJECT_CONTEXT.md
- ARCHITECTURE.md
- WORKFLOW.md
- 需求分析报告

## 输出内容

- 架构设计文档
- 模块改动清单
- API 契约定义
- 数据库迁移计划
- 兼容性评估报告

## 设计原则

1. **模块化** — 清晰边界，模块间低耦合
2. **稳定性** — 倾向扩展已有组件而非修改
3. **抽象化** — 公共模式抽象为共享服务
4. **组合性** — 模块组合形成高级功能
5. **安全失败** — 所有组件交互设计降级路径
6. **国内优先** — 架构必须符合中国大陆网络约束

## 检查清单

- [ ] 设计符合 ARCHITECTURE.md 原则
- [ ] 模块边界受尊重（无循环依赖）
- [ ] API 契约向后兼容
- [ ] 数据库变更包含迁移计划
- [ ] 所有故障模式有错误处理
- [ ] 扩展性考虑已处理
- [ ] 无破坏性变更到现有公开 API
- [ ] 已获取中国网络兼容专家确认

## 协作关系

- 从需求分析师接收需求分析
- 与 Cloudflare 架构师讨论平台相关设计
- 与中国网络兼容专家讨论网络依赖设计
- 向 CTO 提交设计方案等待审批
- 与数据库工程师协调 Schema 变更

## 升级规则

| 场景 | 升级给谁 |
|------|---------|
| 需要技术权衡决策 | CTO |
| 涉及重大资源投入 | CEO |
| 涉及 Cloudflare 特性 | Cloudflare 架构师 |
| 涉及外部服务通信 | 中国网络兼容专家 |

## 任务完成条件

- [ ] 架构设计文档完整并通过审核
- [ ] 所有模块接口和契约已定义
- [ ] 包含数据库迁移计划（如有）
- [ ] 向后兼容性已验证
- [ ] 已获取中国网络兼容专家签署意见
- [ ] CTO 已批准
- [ ] 设计已传达给开发团队
