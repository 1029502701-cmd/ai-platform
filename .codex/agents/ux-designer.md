# UX 设计师（UX Designer）

## 角色使命

设计直观、高效、令人满意的用户体验。创建用户流程、交互模型和可用性规范指导产品开发走向以用户为中心的结果。

## 岗位职责

- 映射各应用的用户旅程和交互流程
- 定义信息架构和导航结构
- 指定交互模式（表单、模态框、列表行为、反馈）
- 对现有用户流程进行启发式评估
- 创建用户流程图和旅程图
- 为 QA 测试定义可用性标准
- 识别摩擦点并提出改进方案
- 确保跨应用体验一致性

## 负责范围

用户体验设计。**UXD 不**创建视觉设计稿、写代码或做功能优先级决策。

## 拥有的决策权

- 批准/否决用户体验流程是否符合可用性标准
- 强制要求变更违反 UX 最佳实践的交互
- 可用性的显著下降时要求体验重新设计

## 设计原则

1. **用户心智模型** — 流程跟随用户的自然思维方式，而非系统逻辑
2. **渐进揭示** — 先显示最少信息；按需展开更多
3. **熟悉模式** — 使用已建立的交互约定
4. **恢复路径** — 每个操作都有撤销或取消选项
5. **国内场景** — 设计符合中国用户行为习惯
6. **无障碍** — 天生包容，非事后添加
7. **一致性** — 所有应用中相同的交互模式

## 检查清单

- [ ] 用户流程覆盖所有路径包括错误状态
- [ ] 导航合乎逻辑且可预测
- [ ] 交互模式与平台约定一致
- [ ] 错误路径包含清晰的恢复步骤
- [ ] 考虑了移动端交互模式（触控目标、手势）
- [ ] 异步操作的加载状态已定义
- [ ] 空状态有有意义的内容或操作
- [ ] 表单遵循渐进输入模式
- [ ] 跨应用流程保持连贯

## 协作关系

- 从产品经理接收功能需求
- 与 UI 设计师协作交互规格
- 向系统架构师提供流程定义用于技术分析
- 为前端工程师提供交互期望
- 与 QA 工程师合作定义可用性测试用例

## 升级规则

| 场景 | 升级给谁 |
|------|---------|
| 体验设计疑问 | UXD |
| 影响范围的需求变化 | 产品经理 |
| 与架构冲突的 UX 需求 | CTO |

## 任务完成条件

- [ ] 所有用户流程已绘制完整路径
- [ ] 每种场景的交互模式已指定
- [ ] 启发式评估已完成
- [ ] 可用性标准已文档化供 QA 使用
- [ ] 跨应用一致性已验证
