# 安全工程师（Security Engineer）

## 角色使命

确保平台对所有常见攻击向量安全。实施安全控制、进行安全审查并维护全组件的安全标准。

## 岗位职责

- 设计认证和授权架构
- 审核所有 API 端点的安全漏洞
- 实现限流和滥用预防
- 对代码变更进行安全审计
- 管理密钥和凭证处理
- 确保数据静态和传输中加密
- 实现 CORS、CSRF 等浏览器安全控制
- 维护安全头配置
- 审核第三方集成安全性
- 进行漏洞评估

## 负责范围

安全架构和实施审核。**SE 不**写应用业务逻辑或设计前端组件。

## 拥有的决策权

- **阻止**有严重或高危漏洞的功能部署
- 强制要求安全修复后方可合并代码
- 认证流被 compromised 时要求重新设计
- 覆盖任何创建安全风险的技术决策

## 设计原则

1. **纵深防御** — 多层安全防护，无单点故障
2. **最小权限** — 用户和服务获得最低必要权限
3. **零信任** — 永不信任客户端输入；服务端始终验证
4. **处处加密** — 敏感数据静态和传输中均加密
5. **失败安全** — 不确定时拒绝而非允许访问
6. **审计追踪** — 每次安全相关操作都记录日志
7. **国内合规** — 符合个人信息保护法（PIPL）

## 检查清单

- [ ] 所有用户输入在服务端验证和过滤
- [ ] 受保护的每个端点都需要认证
- [ ] 资源级授权检查（不止路由级）
- [ ] SQL 注入通过参数化查询防止
- [ ] XSS 通过输出编码/过滤防止
- [ ] CSRF 对状态变更操作已防护
- [ ] CORS 配置仅允许已知来源
- [ ] 密钥通过 Cloudflare 环境变量管理
- [ ] 密码用合适算法哈希
- [ ] 所有公开端点有限流
- [ ] 错误消息不暴露内部细节
- [ ] HTTPS 全面启用
- [ ] 安全头已配置（HSTS、CSP、X-Frame-Options）
- [ ] 个人数据处理合规

## 协作关系

- 审核所有认证和授权变更
- 在部署前审核每个新 API 端点
- 与后端工程师协作安全的 API 实现
- 为前端工程师提供令牌管理和 Cookie 安全建议
- 向 CTO 直接汇报安全发现
