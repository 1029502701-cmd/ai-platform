# 网络策略（NETWORK POLICY）

## 一、域名策略

- **单一自定义域名**服务所有请求
- 所有前端、API、WebSocket 流量通过同一域名
- **绝对不允许向用户暴露 workers.dev 域名**
- 不使用子域名（减少 DNS 查询），用路径区分（/api/*）

## 二、同源策略

- 前端到后端的所有通信尽量使用同源请求
- 同源 = 不需要 CORS Preflight（省一次 RTT）
- 不暴露跨域请求
- R2 上传/下载：使用预签名 URL，浏览器直传，不经过服务器

## 三、DNS 策略

- 每页面加载目标：**最多 3 次 DNS 查询**
  1. 自定义域名（必须）
  2. 外部资源（尽量避免）
  3. 其他（通过同源代理解决）
- 使用 `<link rel="preconnect">` 预连接关键来源
- Cloudflare DNS TTL 最低 300 秒

## 四、TLS 策略

- 目标：**每次会话最多 1 次 TLS 握手**
- 使用 HTTP/2 多路复用，一个 TLS 连接承载所有请求
- TLS 模式：Full (Strict)
- 最小 TLS 版本：1.2
- 启用 TLS 1.3

## 五、重试策略

```
最大重试次数：3 次
退避时间：500ms → 1000ms → 2000ms（指数退避）
可重试状态码：408、429、500、502、503、504
不可重试：400、401、403、404
超时：常规请求 15s，简单请求 5s，AI 生成 120s
```

## 六、超时策略

| 操作类型 | 超时时间 |
|---------|---------|
| 快速 API（认证/资料读取） | 5 秒 |
| 标准 API（AI 处理启动） | 15 秒 |
| 慢速 API（文件上传/大导出） | 60 秒 |
| 页面加载 LCP 目标 | 3 秒 |
| WebSocket/SSE 心跳 | 30 秒 |
| D1 查询 | 10 秒 |
| KV 读取 | 3 秒 |
| AI 提供商调用 | 120 秒 |

## 七、降级策略

```
第 1 层：浏览器缓存 / KV 缓存
  ↓ 未命中
第 2 层：Cloudflare CDN 边缘缓存
  ↓ 未命中/过期
第 3 层：Pages Functions（边缘计算）
  ↓ 失败
第 4 层：优雅降级（返回缓存数据或简化视图）
  ↓ 失败
第 5 层：友好的错误提示 + 重试选项
```

## 八、Cloudflare 限制须知

- Pages Functions 请求体上限：100MB
- Workers 请求超时：30 秒
- KV 单 Key 上限：10MB
- 冷启动：约 100ms 典型，500ms 最差
- 国内 POP：上海、杭州（确保这些 POP 已激活）

## 九、部署建议

- Cloudflare Pages 自动原子化部署，零停机
- 回滚：选择上一个部署，即时生效
- 环境：dev → staging → prod
- 功能开关：KV 驱动的 Feature Flags
