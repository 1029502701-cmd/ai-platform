# 开发流程（WORKFLOW）

## 核心原则

**任何开发都必须经过评审。未经批准不得开始写代码。**

---

## 标准开发流程（所有任务通用）

```
需求提出           [产品经理]
    ↓
需求分析           [需求分析师]
    ↓
产品评审           [产品经理]
    ↓
系统架构评审       [系统架构师 + CTO]
    ↓
Cloudflare 架构评审 [Cloudflare 架构师]
    ↓
中国网络兼容评审   [中国网络兼容专家]
    ↓
开发方案设计       [CTO + 对应工程师]
    ↓
用户确认审批       [CEO → CTO → 相关架构师]
    ↓
开始开发           [对应工程师]
    ↓
功能测试           [测试工程师]
    ↓
QA 检查            [测试工程师]
    ↓
安全检查           [安全工程师]
    ↓
性能检查           [性能优化工程师]
    ↓
文档更新           [知识库工程师]
    ↓
最终验收           [CTO + 所有评审人]
    ↓
部署上线           [DevOps 工程师]
```

## 各阶段详细说明

### 第一阶段：需求提出
- **输入**：用户需求、业务需求或战略方向
- **输出**：初步需求描述

### 第二阶段：需求分析
- **参与者**：需求分析师
- **活动**：
  - 将高层需求拆解为具体的、可验证的需求项
  - 识别技术依赖和约束
  - 评估复杂度和工作量估算
  - 识别影响到的模块和服务
  - 识别国内网络影响
  - 定义验收标准
- **输出**：详细需求文档、影响分析报告

### 第三阶段：产品评审
- **参与者**：产品经理
- **活动**：验证需求是否符合产品愿景，确认优先级
- **输出**：审批通过的需求规格、优先级排序

### 第四阶段：系统架构评审
- **参与者**：系统架构师 + CTO
- **活动**：评估架构契合度、模块改动设计、API 变更、数据迁移方案
- **输出**：架构设计文档、模块改动清单

### 第五阶段：Cloudflare 架构评审
- **参与者**：Cloudflare 架构师
- **活动**：验证平台适配性、函数设计、存储使用、部署策略
- **输出**：Cloudflare 实施方案、绑定配置说明

### 第六阶段：中国网络兼容评审
- **参与者**：中国网络兼容专家
- **活动**：域名配置审核、同源策略合规性、DNS/TLS 优化、降级策略
- **输出**：国内网络兼容性报告、降级方案

### 第七阶段：开发方案设计
- **参与者**：CTO + 具体负责的开发人员
- **活动**：编写详细的开发步骤、任务分配、依赖顺序、测试计划
- **输出**：实施方案、任务分解表

### 第八阶段：用户确认审批
- **参与者**：CEO → CTO → 相关架构师
- **活动**：最终审批，资源分配确认
- **输出**：批准的开发指令

### 第九阶段：开发实施
- **参与者**：对应的工程师
- **活动**：按 CODING_STANDARDS.md 编写代码、同步编写测试
- **输出**：代码变更、单元测试、更新后的文档

### 第十阶段：功能测试
- **参与者**：测试工程师
- **活动**：执行单元/集成/端到端测试、测试国内网络场景
- **输出**：测试报告、缺陷列表

### 第十一阶段：QA 检查
- **参与者**：测试工程师
- **活动**：手动测试、边缘用例验证、UI/UX 一致性检查
- **输出**：QA 审查报告

### 第十二阶段：安全检查
- **参与者**：安全工程师
- **活动**：认证/授权审查、输入验证审计、加密检查、依赖漏洞扫描
- **输出**：安全审查报告

### 第十三阶段：性能检查
- **参与者**：性能优化工程师
- **活动**：请求延迟分析、查询性能、CDN 命中率、国内网络测试
- **输出**：性能审查报告

### 第十四阶段：文档更新
- **参与者**：知识库工程师
- **活动**：更新 API 文档、架构文档、决策记录
- **输出**：更新的文档集、决策记录

### 第十五阶段：最终验收
- **参与者**：CTO + 所有评审人
- **活动**：全流程终检、构建管道验证、部署就绪检查
- **输出**：上线许可

---

## 审批层级

| 任务规模 | 定义 | 需要谁批准 |
|---------|------|-----------|
| 小型 | 单一模块内部变更，<1天 | 对应负责人 Agent |
| 中型 | 跨多个模块，<1周 | CTO + 系统架构师 |
| 大型 | 平台级变更，>1周 | CEO + CTO + 全部相关架构师 |
| 紧急修复 | 生产安全/稳定性问题 | CTO 立即授权，事后补审 |

---

## 紧急情况例外

发生生产级别的严重安全或稳定性问题时：

1. 可先紧急修复，跳过非安全相关的评审环节
2. 必须立即通知 CTO
3. 24 小时内补全所有必需评审
4. 所有紧急修复必须在 DECISIONS.md 中记录
5. 必须进行事后回顾（Post-mortem）
