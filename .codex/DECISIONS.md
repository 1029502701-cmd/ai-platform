## 已有决策记录

### ADR-001：平台部署策略
- **状态**：已批准
- **日期**：2026-07-24
- **决策**：使用 Cloudflare Pages + Pages Functions 作为唯一部署目标
- **理由**：
  - 同域 API 天然支持，符合国内网络兼容要求
  - 无需管理服务器，自动水平扩展
  - Cloudflare 在中国大陆有 POP 节点（上海、杭州）
  - 零停机部署，Git push 即触发
- **影响**：所有后端代码必须运行在 Cloudflare Workers 环境内，不能使用 Node.js 内置模块

### ADR-002：单一域名策略
- **状态**：已批准
- **日期**：2026-07-24
- **决策**：全部流量通过一个自定义域名路由
- **理由**：
  - 避免跨域请求和 CORS Preflight
  - 减少 DNS 查询次数（国内关键）
  - 减少 TLS 握手次数
  - 不被暴露 workers.dev 子域名
- **影响**：前端和 API 必须在同一域名下；R2 上传/下载使用预签名 URL

### ADR-003：数据存储选型
- **状态**：已批准
- **日期**：2026-07-24
- **决策**：D1（结构化数据）+ KV（缓存/会话）+ R2（文件/二进制）
- **理由**：三者均为 Cloudflare 原生产品，零网络延迟，同区域部署
- **影响**：不使用外部数据库（如 PostgreSQL on RDS），不用外部对象存储（如 AWS S3）
