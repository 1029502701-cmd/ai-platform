# AI 开发团队规则（RULES）

## 使命

建立并维护一个结构化、高效、可扩展的 AI 驱动开发组织，用于运营长期生产级 AI SaaS 平台。

## 适用范围

本规范适用于本项目所有 AI Agent 的职责、交互方式、工作流程和交付物。适用于项目中的每一项任务、每一个功能和每一次架构决策。

---

## 任务开始前必须执行的步骤

任何开发任务启动前，必须**按顺序**完成以下步骤：

### 第一步：阅读 RULES.md
了解组织规则和自己的职责边界

### 第二步：阅读 PROJECT_CONTEXT.md
了解项目目标、技术栈、约束条件

### 第三步：阅读 ARCHITECTURE.md
了解当前架构和模块边界

### 第四步：阅读 WORKFLOW.md
了解开发流程和必须经过的评审环节

### 第五步：阅读对应 Agent 文档
了解跨团队协作关系和各自职责

### 第六步：分析影响
评估该任务对现有架构的影响

### 第七步：输出开发方案
生成详细的分步实施方案

### 第八步：等待确认
提交方案给相关人员审核；**未获批准前不得开始编码**

### 第九步：开始开发
仅在获得明确批准后开始实现

### 第十步：完成后验证
- Build 构建通过
- TypeScript 编译通过
- Lint 检查通过
- 向后兼容性验证
- 国内网络兼容验证

---

## 审批层级

| 任务级别 | 涉及范围 | 审批人 |
|---------|---------|-------|
| 小型任务 | 单一角色职责范围内 | 对应负责人 Agent |
| 中型任务 | 跨多个模块 | CTO + 系统架构师 |
| 大型任务 | 架构层面变更 | CEO + CTO + 系统架构师 + Cloudflare 架构师 + 中国网络兼容专家 |

## 规则类别

### 一、组织规则
- 每个 Agent 必须明确自己的使命、职责、范围和权限
- Agent 必须遵守层级汇报关系
- Agent 必须遵循既定的协作规则
- **未经批准，任何人不得编码**
- 所有决策必须记录在 DECISIONS.md 中

### 二、质量规则
- 代码必须符合 CODING_STANDARDS.md 的要求
- 每次变更必须通过构建验证
- 每次变更必须通过向后兼容性验证
- 每次变更必须通过国内网络兼容性验证
- 文档必须随代码同步更新

### 三、流程规则
- 所有工作必须遵循 WORKFLOW.md 定义的流程
- 所有评审完成前不得开始编码
- 架构变更必须通过架构评审
- Cloudflare 相关变更必须通过 Cloudflare 评审
- 用户可见的变更必须通过中国网络兼容评审

### 四、安全规则
- 删除文件必须经过明确授权
- 重命名已有文件必须有正当理由并获批准
- 不得在分配范围之外修改业务逻辑
- 生产配置变更必须经 DevOps Engineer 审核
- 紧急修复必须事后记录并重新审查

---

## 协作原则

### 沟通要求
- 简洁、准确、基于事实
- 引用具体的文件路径、行号、架构原则
- 明确说明自己的假设条件
- 遇到阻塞或不确定的情况，及时升级

### 决策原则
- 遵循已建立的架构和编码标准
- 不确定的时候，升级到对应负责人
- 倾向于小步迭代，不做大规模重写
- 所有非显而易见的决策都要记录下来

### 协作纪律
- 尊重其他 Agent 的职责范围
- 主动共享相关上下文
- 需要输入时明确提出
- 按要求交付输出内容

---

## 违规处理

违反上述规则的行为必须：
1. 立即指出
2. 记录在 DECISIONS.md 中
3. 根据严重程度上报给 CEO 或 CTO
4. 纠正后才能继续

本规则不可违反，适用于所有 Agent，不因任务优先级或紧急程度而豁免。
