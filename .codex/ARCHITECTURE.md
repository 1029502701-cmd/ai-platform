## API 设计原则

### RESTful 风格
- 资源导向的 URL 路径
- 标准 HTTP 方法（GET、POST、PUT、PATCH、DELETE）
- 统一响应格式：`{ success, data, error, meta }`
- 正确使用 HTTP 状态码

### 认证机制
- 除公开接口外，所有 API 都需要有效认证令牌
- 令牌通过 `Authorization: Bearer <token>` 传递
- JWT + Refresh Token 模式

### 响应格式
```json
{
  "success": true,
  "data": { /* 响应数据 */ },
  "error": null,
  "meta": {
    "requestId": "req_xxx",
    "timestamp": "2026-01-01T00:00:00+08:00"
  }
}
```

### 错误处理
- 结构化错误响应，包含机器可读的错误码
- 人类可读的错误消息用于日志
- 安全要求：不得向客户端暴露堆栈追踪或内部细节

### 版本管理
- URL 路径版本控制：`/api/v1/resource`、`/api/v2/resource`
- 向后兼容的变更在同一主版本内
- 淘汰旧版本时发出弃用通知

## 数据库策略

### Cloudflare D1（主数据库）
- 基于 SQLite 的关系型数据库
- 定义了表结构，带迁移文件
- ACID 事务
- 读副本部署在离用户最近的区域

#### 核心表（规划中）
- `users` — 用户账户和认证信息
- `profiles` — 用户档案数据
- `subscriptions` — 订阅计划和计费
- `conversations` — 对话记录
- `messages` — 消息记录
- `content` — 用户生成内容的元数据
- `assets` — R2 资产引用
- `ai_jobs` — AI 任务队列记录
- `prompts` — Prompt 模板定义
- `knowledge_base` — RAG 知识条目
- `audit_logs` — 系统审计日志

### Cloudflare KV（缓存与会话）
- 会话存储（短期用户会话）
- 功能开关（Feature Flags）
- 限流计数器
- API 响应缓存（基于时间的缓存）
- 配置值
- 分布式锁

---

## 存储策略

### Cloudflare R2（对象存储）
- 用户上传的图片、视频、文档
- AI 生成内容的输出（AI 图片、报告等）
- 备份文件和导出包
- 静态资源的 CDN 回源

### 缓存分层
1. **浏览器缓存**：静态资源，长缓存时间
2. **Cloudflare CDN 缓存**：API 响应，根据内容设置不同缓存策略
3. **KV 缓存**：高频访问数据（用户档案、配置）
4. **D1 查询优化**：使用索引，避免全表扫描

## AI 提供商抽象层

### 设计模式
所有 AI 提供商通过统一的接口提供服务：

```typescript
// 抽象接口 — 所有提供商实现此接口
interface AIProvider {
  chat(messages: Message[]): Promise<ChatResponse>;
  generateImage(prompt: string): Promise<ImageResult>;
  transcribe(audio: ArrayBuffer): Promise<Transcription>;
}

// 提供商注册表 — 运行时选择提供商
class AIProviderRegistry {
  get(provider: string): AIProvider;
  fallbackChain(): AIProvider[];
}
```

### 支持的提供商
- OpenAI（GPT-4、GPT-4o、DALL-E、Whisper）
- Anthropic（Claude）
- Google（Gemini）
- Ollama（本地模型，隐私敏感场景）

### 选择策略
- 默认：能力最强的可用提供商
- 降级：失败或限流时自动切换
- 隐私：敏感数据走 Ollama / 本地模型
- 成本：非关键任务使用成本更低的提供商
- 国内访问：优先选择中国大陆可访问的提供商

## AI Queue 设计

### 架构
```
客户端 → Pages Function → 队列记录 → Worker 处理 → 结果存储 → 推送/ SSE 通知
```

### 组件
1. **队列提交**：客户端提交任务，获得任务 ID
2. **队列存储**：任务存储在 D1，状态在 KV 供快速查找
3. **Worker 处理**：专用 Worker 消费队列中的任务
4. **进度追踪**：SSE 或 WebSocket 实时推送进度
5. **结果交付**：完成通知 + 结果存入 R2/D1
6. **重试逻辑**：指数退避重试
7. **超时处理**：任务级和全局超时限制

## 知识库引擎

### RAG 管线
1. **入库**：文档通过管理 API 入库
2. **分块**：智能文档分块
3. **嵌入**：向量嵌入由 AI 提供商生成
4. **存储**：嵌入数据 + 元数据存入 D1（或未来的 Vectorize）
5. **检索**：查询时语义搜索
6. **增强**：检索到的上下文注入到 Prompt 中
